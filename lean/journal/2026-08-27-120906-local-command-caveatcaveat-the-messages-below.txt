  Ran 3 shell commands (ctrl+o to expand)

⏺ The branch's semantic definition of types is deliberately minimal: a type is a
  heap-indexed predicate on machine values, defined by the machine's own
  dispatch metadata rather than by any type system.

  The denotation (SorbetLean/Types.lean)

  The grammar STy is the nominal core plus Sorbet's two special forms:

  lean
  inductive STy where
    | untyped | nilTy | cls (c : ObjId) | nilable (τ : STy)

  def STy.den (h : Heap) : STy → Value → Prop
    | .untyped, _ => True                        -- T.untyped: trivially
  inhabited (gradual)
    | .nilTy,   v => v = .nil
    | .cls c,   v => isA h v c = true            -- nominal: the machine's own
  ancestors walk
    | .nilable τ, v => v = .nil ∨ STy.den h τ v  -- T.nilable

  The load-bearing choice is cls: a value inhabits ⟦Integer⟧ at heap h iff your 
  machine's isA ancestors walk says so at that heap — classOf maps immediates
  like .int n to the Integer class, so Integer/String/Symbol are just
  abbreviations (.cls Boot.integerId, etc.), not separate constructors. So types
  are relative to the heap, which is exactly what makes monkey-patching and
  metaprogramming visible to the definition rather than assumed away.

  A recorded design decision: denotations are pure Heap → Value → Prop, not
  iProp-native. Since the Iris instance uses whole-heap ownP ownership, every
  heap fact is pure relative to the owned σ, so ⌜den h τ v⌝ alongside stateIs h
  is the honest form; a per-object ⟦τ⟧ : Val → iProp is deferred to a future
  GenHeap upgrade and would replace only the lifting, not the content.

  The semantic sig lemmas (SigWitness.lean)

  A "semantic sig" for def f(x) with Sorbet sig A → B is a weakest-precondition
  statement over your actual machine: for every argument in ⟦A⟧, running the
  program from the boot heap, every terminal value denotes B at the terminal 
  heap, and the walk left the pinned method table intact. Lemma #1, for f(x) = 
  if x > 0 then x + 1 else 0 with sig Integer → Integer:

  lean
  def fPost (o : ROutcome) : Prop :=
    ∃ v h', o = .val v h' ∧ STy.integer.den h' v
      ∧ objectTable h' = objectTable hPinned

  theorem f_semtyped (n : Int) :
      stateIs Boot.initHeap ⊢
        WP (running (Machine.init (progF n)).cfg) {{ o, ⌜fPost o⌝ }}

  proved by the rb_walk tactic (the machine walk), with the ∀ over all integers
  entering via the constructor split ofNat 0 / ofNat (k+1) / negSucc k — that
  split is the semantic content of Sorbet's T::Boolean narrowing at x > 0. Lemma
  #2 (g_semtyped, sig T.nilable(Integer) → Integer) does the same for the
  x.nil? occurrence-typing: the nil arm and the symbolic-integer arm, assembled
  over the nilable denotation's constructor forms.

  Three supporting pieces make these honest rather than vacuous:

  - The frozen-table pin: the postcondition carries objectTable h' = objectTable
    hPinned, so table invariance is kernel-checked along the very walk it
    protects (this is why define_method tricks can't be blessed).
  - The vacuity guard (pin_is_load_bearing): at the unpinned bare boot heap the
    same call provably reaches a type-stuck outcome — proof the table premise is
    actually carrying the send.
  - Iris-free closed corollaries (f_safe, g_safe): each lemma is discharged
    through run_adequate_of_wp into a statement about Interp.run itself — "every
    fuel-runner execution terminating in a value yields an Integer-denoted
    result" — no Iris in the statement, which is the exact function your
    difftest SUT executes.

  Recorded gaps

  Two honestly-scoped limitations: only the sound direction (constructor forms →
  denotation) is proved; the inversion (den h integer v → ∃ n, v = .int n)
  needs heap-shape reasoning because payload-core subclassing means a .ref could
  satisfy Integer's denotation at some heaps — deferred to the GenHeap era. And
  the lemmas quantify over argument constructor forms rather than the
  denotation directly, precisely because inversion is missing. There's also no
  container/union/generic coverage yet — that's the S5 coverage backlog.
